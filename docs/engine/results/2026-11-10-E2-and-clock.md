# E2: processors and memory, and what happened to the Windows clock fix

Date: 2026-11-10. Confidence: live-verified, read from CI job logs.
Runs (all on gameDroid bd1d7da, bContain fa00faa):
engine-smp-mem 42904250840, engine-disk 42904250869, engine-gki 42904250881.

## E2 on KVM: PASS

A Linux guest on bvmm with `--cpus 4 --memory 5G` and a virtio disk:

    smp: Brought up 1 node, 4 CPUs
    BIOS-e820: [mem 0x0000000100000000-0x000000017fffffff] usable
    Memory: 5029556K/5242488K available
    CPUS=4
    MemTotal:        5044976 kB
    BVMM-DISK-TEST

Memory above the 32-bit device hole appears at 4 GiB as intended, all four
processors start, and the disk's interrupts arrive on a secondary processor.

One wart: the kernel logged `[Firmware Bug]: CPU 1: APIC ID mismatch. CPUID:
0x0000 APIC: 0x0001` for each secondary processor. On the AMD host the APIC ID
is read from CPUID leaves that had not been set per processor. Fixed in
bContain d6f3dab; not yet re-run.

## E2 on WHP: memory PASS, processors not attempted

`--memory 5G` works on WHP (`MemTotal: 5045712 kB`). WHP still runs one
processor.

## The Windows clock fix did not work, and was withdrawn

What was tried (bContain fa00faa): on WHP, tell the kernel to ignore the
hypervisor (`nopv`) and give it the measured TSC frequency
(`tsc_early_khz=`), so a kernel without Hyper-V drivers would use the TSC.

What happened, on both the Android kernel and the ordinary one:

    tsc: Fast TSC calibration failed
    tsc: Detected 2596.130 MHz processor
    Failed to register legacy timer interrupt
    APIC timer disabled due to verification failure
    clocksource: Switched to clocksource tsc-early

The kernel did take the TSC as its clock. But without Hyper-V telling it the
local APIC timer's frequency, it had to calibrate that timer against another
tick source, and bvmm on WHP has none (no PIT, no HPET). Calibration failed
verification, the kernel disabled the APIC timer, and the guest was left with
no periodic tick at all. The container still ran and printed its output, then
the guest hung instead of rebooting, and the CI steps ran into their time
limits.

The earlier PASS lines in those runs are misleading for that reason: the
checks looked for output, and the output appeared before the hang. The disk
and memory results themselves are sound (the bytes were read and written, the
memory was seen), but the guests did not shut down.

Decision: the default on WHP is back to what it was (bContain d6f3dab). The
Android kernel on WHP therefore still has only a coarse clock, as found in
E0b. The measured-TSC path remains as an explicit option for when it can
work.

What the real fix needs: an emulated PIT on WHP (a tick source to calibrate
and verify the APIC timer against), after which `nopv` plus the TSC frequency
should hold. Alternatively a way to have WHP present an invariant TSC to the
guest, which would stop the kernel distrusting the TSC in the first place;
whether WHP offers that was not established. This is milestone E0c, still
open.

Lesson kept for the test jobs: a test must also require the guest to shut
down cleanly, not just to print the right lines.
